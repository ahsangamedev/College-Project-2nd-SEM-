1. Brief Introduction to the Game

The Snake Game is an interactive desktop game built as a modern Windows Forms application in C# targeting .NET 10.0. The player controls a snake advancing across a 2-dimensional grid. The core objective is to steer the snake to consume food items, thereby earning score points and growing in length, while avoiding boundary walls, self-intersections, and stationary obstacles.

The primary goal of this project is to apply foundational Object-Oriented Programming (OOP) principlesâ€”encapsulation, inheritance, polymorphism, and abstractionâ€”within a graphical event-driven architecture. Game rules, state updates, graphics rendering, audio playback, and file persistence are cleanly decoupled into distinct classes.

Grid Movement & Double-Buffered Canvas Smooth discrete movement across a 25×30 grid (20px cell size). The custom GameCanvas panel uses double buffering to prevent screen flickering during rapid timer ticks.

Flexible Dual-Input Controls Simultaneous support for Arrow Keys and W, A, S, D. Direct command-key processing ensures keystrokes are intercepted before button focus changes.
Intuitive Game State Management Comprehensive UI showing real-time Score, High Score, and Status (Ready, Playing, Paused, Game Over), with Start, Restart, Pause/Resume, and Exit controls.

5. Explanation of OOP Concepts Used

The game design explicitly incorporates the four core pillars of Object-Oriented Programming (OOP) to achieve loose coupling, modularity, and high maintainability without procedural sprawl:

1. Encapsulation (Information Hiding & State Protection)

Internal variables are declared private across all classes to preserve object integrity and eliminate unauthorized state manipulation:

  • In Snake, the body coordinates (List<Position> body) and directional state (currentDirection, nextDirection) are hidden. Movement is restricted to the Move() method.
  • Input Integrity: Snake.SetDirection() strictly validates direction changes to prevent immediate 180-degree self-collisions (e.g., attempting to turn Down while moving Up is rejected).
  • Read-Only Properties: Public properties with getters only (e.g., GameManager.Score, GameBoard.Rows, Position.X, Food.Points) expose state safely without allowing external alteration.
2. Inheritance (Hierarchical Code Reuse)

Inheritance structures domain objects into intuitive parent-child relationships, eliminating redundant declarations:

  • GameObject serves as the abstract base class for all board items, providing shared spatial properties (Position) and requiring a standardized drawing contract.
  • Food : GameObject inherits position logic and introduces food point value (default 10 points).
  • BonusFood : Food extends Food, passing base(position, 20) to specialize score value and visual rendering while reusing all positioning mechanics.
  • Obstacle : GameObject inherits spatial tracking while implementing distinct obstacle graphics.
  • Framework Inheritance: Form1 inherits from Form and GameCanvas inherits from Panel, enabling custom paint overrides and double-buffered window rendering.
3. Polymorphism (Dynamic Dispatch & Uniform Interface)

Polymorphism allows derived classes to override base contracts to deliver specialized behaviors through a common interface:

  • Method Overriding: GameObject defines the abstract method Draw(Graphics g, int size). Derived classes Food (red circle), BonusFood (orange circle), and Obstacle (gray square) override Draw() with customized rendering algorithms.
  • Uniform Execution: GameManager handles food polymorphically: whether it holds an instance of Food or BonusFood, invoking food.Draw(graphics, cellSize) executes the appropriate specialized rendering routine without type casting.
  • System Event Interception: Form1 overrides ProcessCmdKey to intercept arrow key inputs before default Windows Form focus navigation can switch button states.
4. Abstraction (Separation of Concerns & Interface Simplicity)

Abstraction separates high-level domain operations from intricate low-level mechanics:

  • GameObject provides an abstract representation of spatial grid entities without concerning itself with whether an object is edible, hazardous, or stationary.
  • GameManager encapsulates game mechanics, collision math, and timer ticks. The presentation layer (Form1) interacts only through clean operations: StartNewGame(), Update(), and ChangeDirection().
  • GameMusic abstracts Win32 Multimedia API calls (mciSendString via P/Invoke) behind simple methods: PlayLoop(), Pause(), Resume(), and Stop().

7. Limitations & Future Improvements

Current Project Limitations

  • Platform Dependency: Relies on Windows Forms and native Win32 MCI (winmm.dll), limiting portability to Microsoft Windows.
  • Fixed Grid Resolution: Board size is fixed at 25×30 cells (20px each); responsive window resizing is disabled.
  • Local Persistence: High score is saved in plain text (highscore.txt) without online leaderboard integration or encryption.

Proposed Future Improvements

  • Dynamic Power-Ups: Introduce collectibles like speed boosts, slow-motion timers, and obstacle-destroyer pills.
  • Custom Themes & Audio: Add selectable retro arcade, neon matrix, and dark-mode themes with customizable snake skins.
  • Multiplayer & AI Opponents: Implement local split-screen 2-player mode and an autonomous AI snake driven by A* pathfinding.
  • Cross-Platform Port: Migrate the UI layer to .NET MAUI or Avalonia UI to support macOS, Linux, and mobile platforms.
